# CI/CD

[Rootforce CI](https://github.com/Geokerzman/rootforce/actions) запускается при push в `main`,
pull request к `main` и вручную через `Run workflow`.

CI использует Node.js 24.22.2, устанавливает зависимости через `npm ci`, выполняет
production-сборку и проверяет экспорт:

```sh
npm ci
npm run build
python3 scripts/validate_export.py out
```

Проверяются 24 страницы на трёх языках, `lang`, canonical, sitemap, локальные ссылки,
CSS-ресурсы, `robots.txt`, `llms.txt` и страница 404.

Публикация production настроена отдельно на стороне хостинга. Она проверяет результат CI
каждые 5–5,5 минут и публикует только текущий коммит `main` с успешным CI от push или
ручного запуска. Pull request не запускает публикацию.

Сборка выполняется повторно из того же коммита с той же версией Node.js и зависимостями
из lockfile. Новый релиз активируется после валидации. Если HTTPS-проверка опубликованных
страниц не проходит, возвращается предыдущий релиз. Неудачный CI или сборка сохраняют
текущую опубликованную версию.

Публичный репозиторий и результаты GitHub Actions позволяют обойтись без SSH-ключей
или GitHub-токенов в CI. При переводе репозитория в приватный режим потребуется отдельно
настроить доступ хостинга.

Адреса, права доступа, серверные скрипты и инструкции администратора хранятся отдельно
от публичного репозитория. Изменение CI не меняет установленные на хостинге правила деплоя.
